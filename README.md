# 읍면 단위 산불 시공간 위험 예측 및 예방 브리핑 AI — 결과물 v1.1 (2026-09-30)

산림청 산불통계(2011~2026.9, 7,601건)로 읍면별 위험 순위를 만들고, 시군을 고르면 지도·우선순위 표·예방 브리핑이 나오는 대시보드까지 한 번에 만드는 프로그램이다.

## 바로 보기

`dashboard/index.html` 을 더블클릭하면 브라우저에서 열린다. 설치할 것이 없고 인터넷이 없어도 된다(글꼴만 기본 글꼴로 바뀐다).

## 처음부터 다시 돌리기

```
pip install -r requirements.txt
python run_all.py
```

원자료는 아래 위치에 있어야 한다. 용량이 커서 이 zip에는 넣지 않았다.

| 위치 | 파일 |
| --- | --- |
| `raw/산불통계/산불통계 2011~2026.9.xlsx` | 산림청 산불통계 포털 엑셀 |
| `raw/산불통계/산불통계 2022~2025.9.txt` | 공공데이터포털 파일(발생 시각·진화 시각·동리) |
| `raw/bnd/N3A_G0110000.shp, .dbf, .shx, .prj` | 연속수치지형도 읍면동 경계(압축을 푼 것) |
| `raw/읍면동별지목면적/*.xlsx` | KOSIS 지목별 국토이용현황(없어도 돌아감) |
| `raw/토지임야정보/*.csv` | 국토교통부 토지임야정보, 브이월드 '전체데이터' 시도별 CSV 16개(약 5.3GB, 없어도 돌아감) |

`01b_landuse.py` 는 처음 한 번 5GB를 읽느라 3~4분 걸린다. 그 뒤로는 `out/landuse_by_dong.csv` 를 다시 쓰므로 전체 실행이 1분 안쪽이다.

geopandas, shapely, xgboost 없이 돌아가게 만들었다. 경계 파일 읽기와 좌표 변환은 `pipeline/shpio.py` 에 직접 구현했고, 모델은 scikit-learn의 그래디언트 부스팅(HistGradientBoosting, 포아송)이다. 작업 환경에서 xgboost 설치가 막혀 있었기 때문이며, 같은 계열의 트리 모델이라 나중에 XGBoost로 바꾸는 것은 `03_model.py` 의 `make_model` 한 곳만 고치면 된다.

## 검증 결과 (2011~2023년으로 학습, 2024~2026.9 산불 1,156건으로 채점)

| 고른 범위 | 과거 건수 순위(기준선) | 학습 모델 | 처음 보는 지역만 예측 |
| --- | --- | --- | --- |
| 상위 10% 읍면 | 25.5% | 27.1% | 26.8% |
| 상위 20% 읍면 | 41.5% | 44.5% | 41.4% |
| 상위 30% 읍면 | 53.8% | 56.8% | 56.0% |
| 상위 50% 읍면 | 71.9% | 77.1% | 75.2% |
| 시군 안에서 상위 30% | 39.3% | 43.0% | 42.3% |

- 표의 숫자는 "위험 순위 상위 몇 %의 읍면이 실제 산불의 몇 %를 담았나"이다.
- 상위 20%에서 모델과 기준선의 차이는 +3.0%p이고, 시험 산불을 다시 뽑아 계산한 95% 구간은 +0.7~+5.3%p이다. 넘기긴 했지만 차이가 크지 않다.
- 2026-09-30 팀 PC(scikit-learn 1.9.1, pandas 3.0.6)에서 다시 돌린 값이다. v1.0을 만든 환경과 라이브러리 버전이 달라 소수점 첫째 자리가 조금 다르다(예: 상위 10% 27.3→27.1%). 상위 20%와 결론은 같다.
- **읍면 임야·농지 비율은 모델에 넣지 않았다.** 학습 기간 안 검증(2018~2023 구간 4회 평균)에서 상위 20% 포착률이 44.8% → 44.6%로 오르지 않았기 때문이다(시군 안 상위 30%는 40.5% → 41.4%로 조금 올랐다). 넣을지 말지는 시험 기간을 보지 않고 이 검증만으로 정했고, 넣은 모델의 시험 점수는 계산하지 않았다. 비율은 대시보드 읍면 상세에 참고로 표시한다.
- 모델 종류는 학습 기간 안에서만 굴려 본 검증(2018~2023 구간 4회 평균)으로 골랐다. 고르기 전 첫 버전은 시험 기간에서 42.6%였다.
- "처음 보는 지역"은 시군을 5묶음으로 나눠 학습에서 뺀 지역만 예측한 것이다. 상위 20%에서는 기준선과 비슷하다.
- 기획서의 기준선(43%·54%)과 조금 다른 이유: 장소 이름을 정리해 합쳤고, 산불이 한 번도 안 난 읍면까지 전체 1,568곳을 분모로 썼기 때문이다.

## 알아둘 한계

1. **읍면 임야·농지 비율을 만들었지만 순위를 높이지는 못했다.** 토지임야정보로 1,568개 단위 전부에 비율을 붙였다(못 붙인 법정동은 면적 기준 0.5%, 대부분 비무장지대 부근). 과거 발생 이력이 이미 땅의 성격을 대부분 담고 있기 때문으로 보인다. 지목상 '임야'는 실제 숲과 다를 수 있다(산림청 임상도로 보완 가능). 토지 이용은 2026-09 한 시점 값을 전 기간에 썼다.
2. **경계 파일에 접경지역 읍면 25곳이 없다.** 파주 문산읍·파평면·탄현면, 김포 통진읍, 강화 강화읍·선원면, 옹진 백령면, 철원 철원읍·김화읍, 고성 거진읍 등. 이곳 산불 137건은 표와 모델에는 들어가지만 지도에는 안 그려진다. 접경지역까지 있는 경계 파일(통계청 SGIS 읍면동 경계 등)로 바꾸면 해결된다.
3. **'언제'는 전국 공통 계절성이 거의 전부다.** 읍면별 월 곡선이 전국 월 분포보다 시험 산불의 달을 더 잘 맞히지 못했다. 월별 지도는 설명용으로 보고, 시기 예측을 높이려면 기상 자료가 필요하다.
4. **도시의 '동 지역'은 여러 동을 합친 큰 단위다.** 그래서 전국 순위 상위에 몰린다. 시군 안 순위를 기준으로 보는 것이 맞다.
5. **조치 규칙 7개는 모두 근거가 있다(v1.1).** 4개는 팀 기획서, 나머지 3개(담뱃불·건축물 화재 비화·산업현장)는 산림청 전국 산불방지 종합대책(2025·2026)과 산림보호법 벌칙 규정에 맞춰 확정했다. 출처와 초안에서 바꾼 이유는 `docs/rules_basis.md` 에 있다. 종합대책 원문 파일은 아직 확보하지 않았다.
6. 읍면을 알 수 없는 산불 48건(0.6%)은 읍면 단위 분석에서 빠졌다. 오타로 보고 고친 47건은 `out/match_log.csv` 에서 확인할 수 있다.
7. 지침 문서를 검색해 답하는 Q&A는 이번 버전에 없다(지침 원문이 없었다).
